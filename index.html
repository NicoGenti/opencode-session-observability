See exactly what your OpenCode 2 agent did

OpenCode Session Observability opens the session database on your machine and shows the recorded turns, steps, tool calls, tokens, cache reuse and cost as one ordered ledger. Nothing is uploaded.

What it does

Every OpenCode 2 session leaves an event ledger: prompts, assistant steps, tool calls, retries, errors, compactions, tokens and cost. This tool reads that ledger from the local SQLite database and turns it into a filterable transcript, with a per-turn table for the numbers.

It is built for developers inspecting their own runs, on their own machine. The same analysis is available as a local web app and as native panels inside the OpenCode 2 TUI, and neither surface needs a network connection.

Features

  • Trajectory

    A filterable ledger of every recorded event in recorded order: prompts, steps, reasoning, tool calls and results, subagents, retries, errors, compactions and context notices. Filters cover full text, kind, agent, model, provider, tool, status and token ranges, and the detail drawer holds the full payload.

  • Statistics

    A dense per-turn and per-step table with context size, tokens, cache reuse, cost, model, tool and residual time, output speed and status, plus compactions as separate transactions. Basic and Advanced modes control how much of the table is shown.

  • Native TUI panels

    Inside OpenCode 2 the plugin adds fullscreen /statistics and /trajectory panels that render the same analysis in the terminal. Add --web to either command to open the browser view instead.

  • WebUI

    A local browser app served from 127.0.0.1: project-grouped session tree, filters, full-text search, keyboard shortcuts, the OpenCode palettes as themes, and charts in Advanced mode.

  • Export

    Self-contained HTML, Markdown and JSON reports, redacted by default. HTML and Markdown carry the summary, turns, steps, compactions, trajectory and known limitations.

  • Review digest

    A deterministic LLM review digest, capped at 16,000 characters, that you paste into the model of your choice. The app builds the text locally and never contacts a provider.

Install

Requirements: Node.js 22.18+ or 24.x, and an OpenCode 2.x host. The package ships its three bundles prebuilt, so the install needs no build step.

npm install opencode-session-observability
npx opencode-observability --version

Register the plugin in your OpenCode config:

{
  "plugins": ["opencode-session-observability"]
}

Start the local UI once with npm start, then open a panel from the TUI with /statistics or /trajectory.

For a global CLI, install with npm install -g opencode-session-observability. A release tarball is also attached to release v0.1.0.

Security posture

The app is local-first and read-only. The SQLite database opens with SQLITE_OPEN_READONLY and PRAGMA query_only = ON, and the adapter exposes no mutation methods, so sessions, messages and configuration are never written.

The server binds to 127.0.0.1 by default and requires a per-run access token. A non-loopback bind needs --allow-remote and authentication, and requests are rejected unless the Host and Origin belong to the listener.

There is no telemetry, no third-party request and no LLM provider call. Credential-shaped keys are replaced with [REDACTED] by default, and reveal stays opt-in and explicit.

Exports and the review digest are redacted by default. The only network surface is the loopback HTTP API that serves the UI and the plugin RPC.
